## 2. デプロイ先

### 選んだデプロイ先：A. AWS（EC2 + RDS）

| 比べたこと | A. AWS（採用） | B. Render など |
|-----------|---------------|---------------|
| これまでの経験 | Week 11〜17 で構築・HTTPS 化・自動デプロイまで済んでいる | 新しく覚える必要がある |
| 開発時間（26h）への影響 | 環境づくりの時間がほぼかからず、機能開発に時間を回せる | 移行と動作確認に時間がかかる |
| 画像の保存（ローカル） | EC2 のディスクに保存し続けられる | 無料プランではディスクが消えるため、外部ストレージが必要になる |
| 費用 | 無料利用枠内（C-03） | 無料プランはスリープや DB の期限がある |
| 手間 | サーバーの設定・更新を自分で行う | 設定が少ない |

### 選定理由
1. Week 11〜15 で、EC2・RDS・独自ドメイン・HTTPS・GitHub Actions による自動デプロイまで構築済みで、そのまま流用できる。26時間の開発時間を機能開発に使える
2. 画像をローカルに保存する今回の構成では、ディスクが消えない EC2 が向いている
3. 無料利用枠の範囲で動かせる

## 3. 今回は使わない技術

| 技術 | 使わない理由 | 使う予定の機能 |
|------|-------------|---------------|
| React / Vue | Blade の Web アプリとして作る（C-05）。Ajax はいいね1か所で、fetch で足りる | — |
| AWS S3 | 画像はローカル保存にした（26h に収めるため） | F-33 画像の S3 保存（Could） |
| Stripe | グッズ・チケット購入を今回は作らない | F-12, F-14（Could） |
| メール送信（SES・Mailpit） | お問い合わせは DB 保存のみで、メールを送らない（C-07） | 購入完了メールなど（Could） |
