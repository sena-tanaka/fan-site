# 練習課題1：ECサイトのスプリント計画

> 総合プロジェクトとは別の練習用の題材。Week 19 の[画面設計](./ec-screen-design.md)と同じ、架空の雑貨ECサイト「MONO STORE」の開発を3つのスプリントに分け、タスクを割り当てる。

## 1. 前提

| 項目 | 内容 |
|------|------|
| 体制 | 開発者1人 |
| スプリントの長さ | 1週間 × 3スプリント |
| 1スプリントで使える時間 | 30h（このうち 2〜3h は予備として残す） |
| 使用技術 | Laravel / Laravel Breeze / MySQL / Docker / Stripe（テストモード）/ AWS |
| 見積もりの単位 | 時間（h）。0.5h 刻み |

## 2. スプリントの分け方

「お客さんが使う順番」に合わせて、**見る → 買う → また来てもらう・運営する** の3段階に分けた。
各スプリントの終わりに、その段階までの機能が実際に動く状態にする。

| スプリント | テーマ | スプリントゴール |
|-----------|--------|----------------|
| Sprint 1 | 商品を見られる | トップ・商品一覧・商品詳細で、商品を探して中身を確認できる |
| Sprint 2 | 商品を買える | 会員登録してカートに入れ、Stripe（テスト）で購入でき、注文履歴を確認できる。本番環境に一度デプロイする |
| Sprint 3 | 運営でき、また来てもらえる | 管理者が商品・注文を管理でき、お気に入り・レビュー・ランキングでリピートを促せる |

- 一番難しい決済（Stripe）を真ん中の Sprint 2 に置き、問題が起きても Sprint 3 で取り返せるようにした
- 本番デプロイは最終スプリントにまとめず、Sprint 2 で一度行い、本番だけで起きる不具合を早めに見つける
- 管理画面は Sprint 3 にした。それまでは商品データをシーダーで入れれば、お客さん向けの画面を作って確認できるため

## 4. 遅れたときに削る順番

各スプリントのゴールに直接関わらないものから削る。

1. T-22 お知らせ … フッターや固定ページで代わりに告知できる
2. T-21 ランキング … 新着アイテムがあれば商品は見てもらえる
3. T-19 お気に入り
4. T-06 絞り込み・並び替え … カテゴリ別の一覧と検索があれば商品は探せる
5. T-20 レビュー … 購入の決め手になるので最後まで残す

決済（T-12）・在庫（T-13）・商品管理（T-17）は、ないと ECサイトとして成り立たないので削らない。
