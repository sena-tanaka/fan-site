# ヒアリングシート：BEAT CREW 公式ファンサイト

> 架空のクライアント（ダンスチーム運営）へのヒアリングを想定して作成。
> ここで聞いた内容をもとに、[要件定義書](../requirements.md)を作成している。

## ■ プロジェクト概要
- **プロジェクト名**：BEAT CREW 公式ファンサイト（チーム名は仮）
- **ヒアリング日時**：2026年10月17日（土）
- **参加者**：
  - クライアント：BEAT CREW 運営責任者（架空）
  - 開発担当：自分
- **目的**：公式ファンサイト制作にあたり、現状の困りごと・理想の姿・条件を確認する

## ■ 現状の課題
- **業務フロー**：
  - 出演情報：決まり次第SNSに投稿している
  - チケット販売：公演ごとに異なる外部のチケットサイトで販売している
  - グッズ販売：オンラインサイトが別にある
  - ファンとの交流：SNSでの告知が中心で、メンバー個人の発信は少ない
- **課題点**：
  - 「次のライブはいつ？」という問い合わせがSNSによく届く。投稿が流れてしまい、ファンが出演情報を見つけにくい
  - チケットの販売サイトが公演ごとに違い、ファンから「どこで買えばいいの？」と聞かれ、迷うファンもいる
  - グッズが別のオンラインショップになっているので、検索して探すのが手間になっている
  - ライブがない期間は、ファンとのつながりが薄くなってしまう
  - ファンから「メンバーの普段の様子をもっと知りたい」という声が多い
- **解決したいこと**：
  - 出演情報・チケット・グッズの窓口を公式サイトにまとめたい
  - ライブがない日も、ファンがチームを身近に感じられる仕組みが欲しい

## ■ 目指す姿
- **システム導入後の理想**：
  - ファンが公式サイトを見れば、出演予定がすぐ分かり、チケットもグッズも迷わず買える
  - メンバー自身がファン向けに日常を発信でき、ファンが反応を返せる
  - ファンが毎日のようにサイトを訪れたくなる
- **期待する効果**：
  - 出演情報やチケット購入先に関する問い合わせが減る
  - 公式窓口が明確になり、ファンが迷わずチケットを買えるようになる
  - ライブがない期間もファンの熱量を保てる
  - グッズ購入ページに迷わずたどり着けるようになり、グッズの売上が伸びる
- **成功の基準**：
  - 公演チケットの購入が公式サイト経由で行われている
  - 会員登録数が増え続けている
  - 会員の多くが、ライブがない週もサイトを訪れている（おみくじ・ブログの利用）

## ■ 制約条件
- **予算**：原則0円（AWSの無料利用枠の範囲内）
- **納期**：Week 22〜24の3週間で、必須機能を完成させる
- **技術的制約**：
  - Laravel / Docker / AWS など、これまでに学んだ技術で開発する
  - 決済はStripeのテストモードを使用し、実際の決済は行わない
  - 動画はYouTubeの埋め込みで表示する
- **法律・規制**：
  - 個人情報保護法：会員情報・配送先などの個人情報を適切に管理する
  - 特定商取引法：オンライン販売を行うため、販売者情報などの表示が必要
  - チケット不正転売禁止法：転売対策として、チケットは会員限定・1公演につき1人2枚までとする
  - 著作権：画像や素材は自作またはフリー素材を使用する
